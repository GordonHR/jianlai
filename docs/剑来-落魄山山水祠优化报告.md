# 剑来 · 落魄山 / 山水祠 叙事模块「全部优化」报告

> 范围：落魄山（`sect.js`）+ 山水祠（`shenci.js`）两条叙事线。
> 红线：**两端都要**（PC + 小程序一致）、**贴合原著**、**零数值 / 零阵营改动**、配图遵循用户更正后的铁律「**不要乱配图**」（可用立绘提质感，但必须贴合原著、去 AI 化、不堆无意义装饰）。
> 日期：2026-09-02

---

## 一、先查证再动手（非凭记忆）

| 模块 | PC 体量 | 小程序体量 | 逻辑移植度 | 小程序演出/音频层（优化前） |
|---|---|---|---|---|
| **落魄山** sect | 2595 行 | 1904 行 | 54 抉择点 / ~17 结局 两端一致 | `sectBanner/sectFloat/sectFXInit/sectFXClear` **全空函数**，`SFX` 全 no-op → 结局墨滴晕开、回合横幅、资源飘字、喊声**全程不显示**；且 `s.fxQueue`（资源增减）**无 `sectSpawnFx` 消费**，资源飘字永不出现 |
| **山水祠** shenci | 1703 行 | 1299 行 | 7 结局 两端一致 | `scBanner/scFloat/scFlushFx` 空壳，`SFX` 空 → 无声；`scFlushFx` 仅清空 `fxQueue` 不绘制 → 特效未真正落地 |

**核心结论**：两个模块的玩法逻辑两端已高度对齐，差异几乎全在「演出/音频层」——小程序端这层是空壳。这正是「两端都要」红线的直接命中点。

## 二、已落地的优化（P0 / P1 / P3）

### P0 · 落魄山小程序演出层移植（最大缺口，已闭环）
- 实现 `sectBanner`（回合横幅，**一次一个队列**，与 PC 同）、`sectFloat`（资源飘字）、`sectSpawnFx`（消费 `s.fxQueue` → 可见飘字）、`sectFXInit/sectFXClear`。
- `view()` 新增 `fxBanners / fxFloats` 快照，WXML 加 `.sect-fx` 覆盖层，WXSS 移植 PC 的 `.sect-fx-banner / .sect-fx-float` 与**结局墨滴晕开**（`sectInkSpread` → rpx）。
- `SFX` 由全 no-op 改为 `wx.vibrateShort` 轻量震动（小程序无 WebAudio，不堆音频资源、不吵）：click=light、forge/breakout=medium、win/lose=heavy。
- 效果：小程序落魄山现在**有回合横幅、资源飘字、结局墨滴动画、震动反馈**，与 PC 1:1。

### P1 · 山水祠小程序特效真正渲染（已闭环）
- 实现 `scBanner / scFloat / scFlushFx`（错峰 130ms 飘起，避免一坨同时浮），`view()` 挂 `fxBanners / fxFloats`，WXML 加 `.sc-fx` 覆盖层，WXSS 移植 PC `.sc-banner / .sc-float`（按资源类型着色：香火/气数/阴德/威灵…）。
- `SFX` 接 `wx.vibrateShort`。
- 效果：山水祠小程序**神道天劫、受香、资源增减、回合横幅**全部可见可感，与 PC 对齐。

### P3 · 立绘 / 配图（按更正后「不要乱配图」铁律）
- **落魄山 · 人物志**：补角色立绘——`view()` 人物志列表新增 `art/hasArt`，WXML 在每张 `fig-card` 顶部渲染 `<image src="/assets/portraits/{{art}}.jpg">`，`hasArt` 为假时显示姓名占位（`no-art`），**无图绝不强塞占位**（贴合"不乱配"）。
- **山水祠**：主界面/择地已有印章图（`sealImg`）；神是"应或不应当"的抽象主体，强行塞立绘属"乱配"，故**保持文字叙事**，仅在结局/天劫处用横幅与飘字烘托——符合"不要乱配图"纪律。

## 三、P2 设计深度审计（已做，结论：无 bug，未擅改设计）

用小程序端自走探针（`_narr_smoke.cjs`，各 120 局）跑通整局并审计结局可达性：

- **落魄山**：`sectRouteEnding(s, grade)` 按 flag/道契打分选路线归宿（tuoyue/jianqi/wensheng/yingguan/ningyao/ruanxiu/gujiao/peiqian/shanshui），并有完整兜底：`剑礼`均衡且守心稳 → `zhixing_end`，否则 → `pacify`；飞升之争 trial≥4 → `ascend`。失败结局（demon/broken/lost/ruined/bankrupt）由资源条件触发。**无死结局 bug**。随机首选项总偏 `ningyao_end` 是因"宁姚为最常见同伴路线"，属设计使然。
- **山水祠**：`scRouteEnding(s)` 有完整优先级链——正神(S)/山君(A)/守土(B)/脱根(C)/淫祠(D)/沉江(C)/消解(D) 七结局**皆可按特定条件触发**；另有即时危机结局（沉江/消解）。高阶结局（正神需 rank≥3 且阴德≥38、山君需 rank≥2）需长期经营，朴素随机玩不到属正常设计深度，**非 bug**。

**审计处置**：发现分支健全、无不可达结局。属"设计级重塑"（如让高阶结局更易达、或加结局图鉴引导）的部分**不做擅改**——那会动设计根基、违反红线。仅在报告中建议（可选）：未来可在「祠务·上晋」面板已明示的需求之外，补一句"结局走向提示"，帮助玩家理解长期经营目标。本轮回不做。
