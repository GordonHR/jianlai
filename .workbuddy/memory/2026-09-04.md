## 第 11 轮：太平无事牌 · 修 writing-mode 把 row-reverse 旋转成上下堆叠的根 bug（先放最前，铁律永久）

用户截图（n:13 陈平安那张）原话：\"不仅每改好，还更差了……你就固定每列12个汉字，多折行，从右往左\"。

**根因**：`.wsp-dt-txt` 同时设了 `writing-mode:vertical-rl` 和 `flex-direction:row-reverse`。CSS 规范下，writing-mode:vertical-rl 容器内 inline 轴 = 物理垂直方向，所以 `flex-direction:row`（含 row-reverse）实际上是**上下堆叠**而非横向并排。这就是为什么 11 字（后改 12 字）只能显示一列就被截——不是 max-height 限制，而是 cols 在物理垂直方向堆成一行，第二列被推到 panel 外被 hidden 截掉。

**修法（PC + 小程序两端 1:1）**：
- `.wsp-dt-txt` **撤掉 writing-mode**，仅作 flex 横排容器（`display:flex; flex-direction:row-reverse`）。
- writing-mode 只给 `.wsp-dt-col`（每列内部文字竖排）。
- `wspSplit` per=12（用户明示固定 12 个汉字），n:10 t=20 字 → 2 列；n:6 31 字 → 3 列；n:8 35 字 → 3 列；n:13 15 字 → 2 列。
- 弹框 width 400→420，panel padding 52/40 → 48/36，line-height 1.9→1.7（12 字 × 22px × 1.7 = 449px，弹框 panel 可用 ≈546px，安全余量 100px）；小程序端 34rpx→32rpx、line-height 1.9→1.7。

**改动文件**：`wushipai.js`（wspSplit per 11→12）、`index.html`（.wsp-dt-txt 撤 writing-mode + 行高调 + 弹框宽度 400→420、bump `?v=20260903p`）、小程序 `wushipai.{js,wxss}` 同步。
**门禁加固**：
- T23 新增两条关键正则断言（防重犯）：① `/wsp-dt-txt[^{]*\{[^}]*writing-mode/` 必须不存在（防 bug 重犯）；② `/wsp-dt-col[^{]*\{[^}]*writing-mode:\s*vertical-rl/` 必须存在。
- T23 新增 `wspSplit.per=12` 断言（probe `wspSplit('15字')` 必须返回 2 列、首列 12 字）。
- T19/T23 的 `column-count` substring 检测改为正则 `\\bcolumn-count\\s*:`（之前 CSS 注释里写了\"column-count\"字样触发 substring 误报）。

**铁律（永久）**：
- **writing-mode 必须只在最内层竖排容器上**——设在外层 flex 容器会把 flex direction 旋转走（row → 上下、column → 左右），破坏布局。
- **每列固定 12 字**（用户 2026-09-04 明示）作为基准 per，不做自适应档位。
- 不要再引入 CSS `column-count` / `column-fill`（writing-mode 下不可靠）——纯 JS slice + 多个 .wsp-dt-col span + flex 横排才是稳定方案。
- CSS 注释里出现 `column-count` 这种字符串会触发 substring 门禁误报，门禁必须用更精确的正则 `\\bcolumn-count\\s*:`（匹配规则而非注释）。

## 第 10 轮：太平无事牌 · CSS column 在 writing-mode 下不可靠，撤回用 JS 按字数切列

承接第 9 轮的"CSS column-count 自动折列"。用户截图（n:13 陈平安，14 字）反馈"为啥这个字就是不能到底再折行呢"——字虽折成 4 列但每列只占弹框 ~30% 高就折了，没写到底。

**根因**：`writing-mode:vertical-rl + column-count:N + column-fill:auto + max-height:100%` 行为：N 等分列高（max-height/N），字少时列数被 N 强制撑开 → 每列字数少、高度远低于弹框。CSS column 在竖排下行为不可靠，Chromium 微信小程序均如此。

**修法（两端 1:1）**：改回 **朴素的 JS 按字数切列**（不带字号档位/首列空格那种复杂版）：
```js
function wspSplit(t){
  const per = 11; // PC 22px/1.9 → 11 字 ≈ 482px（写到弹框 ~600px 高的 80%）
  const cols = []; for(let i=0; i<len; i+=per) cols.push(t.slice(i, i+per));
  return { cols };
}
```
+ CSS 改用 **flex 横排**：
```css
.wsp-dt-txt { display:flex; flex-direction:row-reverse; ... writing-mode:vertical-rl; gap:.4em; max-height:100%; }
.wsp-dt-col { writing-mode:vertical-rl; text-orientation:upright; white-space:nowrap; }
```
每列字数固定 11，从右往左排，**每列写到弹框底再折下一列**。

**改动文件**：`wushipai.js`（PC，+wspSplit、wspDetail 用 colHtml 拼 .wsp-dt-col spans）、`index.html`（.wsp-dt-txt 改 flex + 加 .wsp-dt-col、bump `?v=20260903o`）、小程序 `wushipai.{js,wxml,wxss}` 同步。
**门禁**：T19/T23 的 `column-count` 断言从"必须存在"再翻为"必须不存在"（撤回 CSS column）；T23 新增：`.wsp-dt-col` 必须存在 + `.wsp-dt-txt` 必须 `flex row-reverse` + 弹层 `.wsp-dt-col` 出现次数 ≥2（n:10 的 t 17 字 → 每列 11 → 应切 2 列）。

- **超 2MB 时的优化优先级**：① 单张体积最大的非核心图（封面/背景/海报）→ ② 故事图批量降一档 → ③ 砍非必要资源。**别上来就批量压故事图**，单张大图 1-2 张通常就能省 50-100KB
- **横版背景/海报在手机端走"裁左右 + 缩 540 + q35"通用配方**（`_shrink_bg.py` 可复用模板）
