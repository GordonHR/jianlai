## 笼中雀配图"仍全黑"的真根因（11:36 用户二次反馈后查清）
- **上一轮我的修法本身有缺陷**：我直接改了**生成物** `packageLongque/utils/longque.js` 的数据（`assets/longque/` → `/packageLongque/assets/longque/`），但**渲染代码仍在拼 `'/'+nd.img`** → 产出 `//packageLongque/...`（双斜杠=协议相对地址）→ 小程序 image 直接加载失败，**仍然全黑**。原版（相对数据 + `'/'+`）则是 `/assets/longque/...` 指向主包已搬走的位置，同样坏。两次都黑，坏法不同。
- **正解＝改同步脚本模板，不改生成物**：`prototype/_lq_sync_weapp.cjs` 里加 helper `function lqAbs(p){ if(!p) return ''; p=String(p); while(p.charAt(0)==='/'){ p=p.slice(1); } return '/packageLongque/'+p; }`，把 `'/'+nd.img` / `'/'+LQ.il.img` 换成 `lqAbs(...)`，再跑脚本重生成。数据层保持 PC 相对写法（`assets/longque/x.jpg`），路径转换集中在渲染层一处。
- **踩坑（模板字面量吃转义）**：我第一版在模板字符串里写 `replace(/^\/+/, '')`，模板字面量把 `\/` 还原成 `/`，生成的 JS 变成非法正则 `/^/+/` → **整个笼中雀模块 SyntaxError**。教训：**同步脚本是模板字面量时不要放正则转义**，用 `charAt/slice` 这类无反斜杠写法。
- **验证**：新写校验（读生成源码抽 `"img":"..."` → 补前缀 → 查文件）：**6 张场面配图全 OK、缺失 0、双斜杠 0；运行时 a1 = `/packageLongque/assets/longque/well_dawn.jpg`**；15 个结局图标文件数与结局数一致。
- **笼中雀图片总数 = 21**：场面大图 6（well_dawn 天不亮的井 / alley_beating 羡阳与挨打的孩子 / red_coat 红棉袄 / well_cool 井边的凉 / forge_fire 炉火旁 / stranger_sword 外乡人的影）+ 结局图标 15。
